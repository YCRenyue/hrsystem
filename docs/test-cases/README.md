## 结论

部署和端到端链路是通的：前端、后端、数据库都在运行，花名册、考勤、食堂、年假、社保、请假的导入都能用，出差到报销的审批流程完整走通。

但有 4 个问题建议在交给 HR 正式使用前修复：

| 优先级 | 问题 | 位置 |
|------|------|------|
| 高 | 综合报表三个报表全部返回 500 | `backend/src/services/ReportService.js:77,163,265-289` |
| 高 | 接口限流每 15 分钟 100 次，正常使用十几分钟就会被锁 8 分钟 | `backend/src/app.js:41` |
| 高 | 出差时间按 UTC 存储、按浏览器时区显示，国内会显示成 +8 小时 | 出差表单与详情页 |
| 高 | 离职花名册导入时，离职人员会被当成在职员工 | `backend/src/services/employeeImportService.js:175` |

### 新发现的问题

| 编号 | 模块 | 问题 | 严重程度 |
|------|------|------|------|
| R2-01 | 出差、报销 | 页面时间按浏览器时区显示。纽约浏览器里填 10-23 09:00~17:30，保存的是北京时间 09:00~17:30（正确），但列表、详情、报销单都显示成 10-22 21:00 ~ 10-23 05:30，提交和审批时间也是纽约时间。编辑待审批单时表单会带入偏移后的时间，再保存就会把错误时间写回库。原因：提交时发送不带时区的本地时间（`BusinessTripForm.tsx:216`），显示时用 `dayjs(带 Z 的时间)`（`BusinessTripList.tsx:160`、`BusinessTripDetail.tsx:232`）。HR 在国内使用不会出现，但在海外或时区设置不对的电脑上会出错 | 中 |
| R2-02 | 员工列表 | 入职日期列用 `new Date(date).toLocaleDateString()`（`EmployeeList.tsx:343`），纽约浏览器显示早一天（马达 2006-10-01 显示为 9/30/2006），格式也随系统语言变化；详情页正确 | 低 |
| R2-03 | 综合报表-考勤 | 每日考勤的“工作时长”全部是 0.0 小时，总工作时长和总加班时长也是 0；导入时没有计算 work_hours（`punch/attendancePunchImport.js`） | 中 |
| R2-04 | 考勤 | 考勤页 TOP 榜用打卡机汇总（祝青迟到 15 次 399 分钟），综合报表用每日打卡按 08:00 判断（祝青迟到 12 次 275 分钟），同一人两处数字不同；全公司迟到 148 次与 23 次差距更大。需要 HR 确认以哪个为准 | 中，待确认 |
| R2-05 | 综合报表 | 首次打开时用了默认日期范围（入离职近一年、请假和考勤近一个月，请假还默认只看已批准），但日期框显示为空、状态显示“全部”；点“查询”后范围消失，结果变了 | 低 |
| R2-06 | 花名册数据 | 2 人的出生日期和身份证不一致：RH-0229 周权（身份证 1992-12-22，表里 1992-12-02）、RH-0182（身份证 1966-12-23，表里 1968-12-23）。系统照表导入。建议预览时提示不一致 | 低 |
| R2-07 | 制度确认 | “总员工数”为 105，包含已离职的周权，待签署也算上了他 | 低 |
| R2-08 | 出差 | “跨越天数”显示 0.35 天（8.5 小时 / 24），HR 可能理解为 1 天 | 低，待确认 |
| R2-09 | 考勤、食堂导入 | “匹配员工 89 / 159 人”的分母包含整个周期没打卡的人，但未匹配名单只列有打卡的 4 人，数字对不上容易误会 | 低 |
